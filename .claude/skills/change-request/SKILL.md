# /change-request

Create a structured change management request with full impact analysis and rollback planning.

## Usage

```
/change-request $ARGUMENTS
```

## Workflow

### 1. Define the Change

- What is being changed (system, process, configuration)
- Why the change is needed
- Scope and boundaries

### 2. Impact Analysis

- Affected systems, services, and users
- Dependencies and upstream/downstream impacts
- Performance or availability implications
- Security and compliance considerations

### 3. Risk Assessment

- What could go wrong
- Probability and severity of each risk
- Pre-change mitigation steps

### 4. Rollback Plan

- Rollback triggers
- Rollback procedure step-by-step
- Data preservation and recovery steps
- Time to rollback

### 5. Communication Plan

- Stakeholders to notify
- Timing of communications
- Channels and owners

## Output

Standard change request document suitable for CAB review and audit.
